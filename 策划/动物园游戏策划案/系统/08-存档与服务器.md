# 存档与服务器

一句话职责：存档内容、保存与同步时序、版本迁移与多设备冲突处理。

## 存档内容【建议】

至少保存：账号和存档版本、配置版本、递增修订号、棋盘及物品实例、背包、待领奖励、货币体力和时间锚、生成器次数及当前轮快照、已建园景 ID、任务完成／入卡状态、解锁隐藏物品、各引导进度、物品发现、签到循环／上次日、广告额度／累计／未决操作、气泡剩余时间、100% 收尾及完成提示状态。

## 服务器方向【沿用】

沿用 HTTPS 及现有服务器方向：工程 `D:\node\wenodejs`、域名 `https://www.farain.com`。真实接口路径未约定，本节只定义所需能力，不声称已有接口：取得时间与服务日、登录／读档、按操作 ID 提交状态变更、查询未决交易、广告奖励核验。现有假 GMRemoteAdapter 不等于正式服务。

## 保存与重试

每次有效状态变动先在本地形成完整结果和操作 ID、保存成功后反馈，再按序同步。网络失败保留待同步队列，不重新抽奖；服务端同一操作 ID 只接受一次。收到成功回应后删除已同步项。关闭发生在反馈前不重放扣料，只补表现或提示。

【建议】服务端用存档修订号防止旧快照覆盖新存档；多设备同时进入时保持单一有效会话，另一台提示重新载入，不自动合并棋盘。账号不可用或存档损坏提供重试，不擅自新建覆盖旧档。平台广告与钻石交易只在能确认服务端结果时完成；结果未明显示"处理中"，禁重复发起该交易，允许查看其他界面。

## 版本变更与迁移

配置安装包加载，首版不承诺热更新。配置改版须有迁移版本：物品与园景 ID 不复用，已建 ID 保留；任务调整对已完成保持完成，当前卡优先映射保留；删物品须有明确替代，不能丢弃棋盘物品。引导变更须按稳定步骤含义映射，不能直接把旧计数套进全新步骤。旧恢复轮快照保留，下一轮才用新参数，避免改表吞次数。

## 启动时序

加载本地设置、配置与必要资源 → 取得服务器时间 → 拉取／创建账号存档 → 进入首页。失败与校时的界面处理见 [页面/01-加载.md](../页面/01-加载.md)；服务器日与时间锚点见 [02-体力与时间.md](02-体力与时间.md)。
